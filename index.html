CAPABILITY SPECIFICATION

Engineered for Ephemeral Utility

A restrained, robust feature set built on open browser standards without invasive trackers or always-on telemetry.

01 / TRANSPORT

Browser-to-Browser WebRTC

Direct peer-to-peer data channels bypass central databases. Chat messages and binary document chunks flow over encrypted DTLS sockets directly between connected browser instances.

02 / PRIVACY

Zero Account Registration

No user accounts, emails, or phone numbers. Ephemeral session tokens reside exclusively in URL fragment hashes (#key=...), preventing server-side leakage in HTTP referrers.

03 / DOCUMENTS

10 MiB Binary Transfers

Native document streaming for PDF, Word, Excel, PowerPoint, Text, and OpenDocument formats. Sliced into 16 KiB chunks with backpressure throttling and zero Base64 inflation.

04 / INTEGRITY

Cryptographic SHA-256

Bit-for-bit file verification calculated in hardware via the Web Crypto API (crypto.subtle). Tampered or corrupted chunks are detected before enabling downloads.

05 / LIFETIME

Absolute Auto-Destruction

Preset durations (5m, 10m, 15m, 20m) or custom values (1–60m). Countdown reflects absolute wall time; message activity does not prolong the session, guaranteeing timely destruction.

06 / AUTHORITY

Creator Expiry Control

The room creator holds exclusive authority to extend active sessions on the fly up to a strict 4-hour ceiling. Guest interfaces synchronize time updates in real time without page reload.

PROTOCOL WALKTHROUGH

How It Works in 3 Steps

Zero setup, zero configuration. Connect and converse in seconds.

01

Generate or Enter Code

Generate a unique 6-character room code in 1 click, or paste an invitation code shared by a peer. Ambiguous glyphs (0, O, I, l) are strictly excluded.

02

Share Invitation or QR

Send the full invitation URL containing the session secret, or present the live vector QR code for instantaneous smartphone camera scanning.

03

Converse & Auto-Destruct

WebRTC negotiates an in-memory direct channel. When the countdown reaches 00:00, all active sockets sever, in-memory Blob URLs revoke, and RAM wipes cleanly.

INTERFACE GUIDE

Feature Navigation

Essential operational details for navigating Anomoly Chat effectively.

Creating a Room

Click "Create Room" to instantiate a room authority. Share the secret-bearing URL fragment to broker direct peer connectivity.

Joining via Code

Input the 6-character room identifier and press Enter. The client automatically validates code format before contacting signaling.

Sending Messages

Press Enter to dispatch messages; Shift+Enter creates a new line. Messages are strictly capped at 500 characters and rate-limited to avoid socket flooding.

Sharing Invitations

Click "Invite / QR" inside an active room to display the vector QR code or invoke native system share sheets via the Web Share API.

Leaving a Room

Click "Leave" to cleanly sever WebRTC DataChannels, revoke in-memory object URLs, and purge conversation logs from client RAM.

Duration Extension

The room host can click the countdown pill to open the extension popover and add +5m, +10m, +15m, +20m, or custom duration up to 4h.

HONEST DISCLOSURE

Privacy & Security Boundaries

Transparent technical disclosure of what this browser-first architecture does and does not protect.

Architectural Reality & Threat Model

Anomoly Chat provides ephemeral, accountless communication between cooperating browser nodes. "Anonymous" indicates zero personal account credentials or phone numbers are harvested. It does not mean undetectable across global network infrastructure.

IP EXPOSURE

Direct WebRTC UDP connections inherently expose public IP addresses to connected peers during ICE candidate negotiation.

SIGNALING

Public signaling servers (0.peerjs.com) broker initial SDP offer/answers; connection timestamps and IP metadata are observed during handshake.

FIREWALLS

Direct peer connections rely on STUN hole-punching. Restrictive enterprise firewalls or symmetric CGNAT may require TURN relays.

LOCAL FILES

Once a binary document is assembled and downloaded to a recipient's local disk, it cannot be remotely recalled or wiped.
